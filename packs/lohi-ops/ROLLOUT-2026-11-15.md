# Rollout 2026-11-15: content loop (auto-ingest, no blind onboarding, quality by mail, tool-first exec loop)

This file is the exact list of steps a PERSON runs to bring the server (soot.lohi2.com, Soot 0.20.0) and the founder's Mac
(Soot 0.20.0) to this source. Nothing here was applied: the work that produced it touched only `packs/lohi-ops/`.

What changes for the live system, in one paragraph: the Mac builder now runs approved jobs itself (`catalog_jobs_pull {autorun: true}`),
a new schedule `ops-radar-scan` finds new chapters, the curator's `catalog_jobs_sync` turns finds into `refresh` jobs
(`approved_by: policy:radar`, 10 a day, only for novels with readers) and now carries the curator key so request stages and refunds
actually reach the api, quality requests go to Catalog Exec by work mail, and every Catalog Exec loop schedule is tool-first.

Order matters: **server first, then Mac**. A radar find the old `catalog_jobs_sync` reads is skipped for good (it advances its cursor).
Do the Mac only after step 6 passes.

Paths below: `$SERVER_CONFIG` = the server runtime's config dir (the merged `flock.json` is `/etc/soot-lohi/flock.json`), `$MAC_CONFIG` =
`~/.soot/nest` (`deployment.json`). `runtimes/server/config/flock.json` and `runtimes/mac/config/deployment.json` in this repo are
**older snapshots** (they lack the exec loop schedules, the Moderator and Catalog Exec entries): the deltas below are written against
what `deployment.fragment.json` already says the live runtimes hold, not against those snapshots. Diff the live file before you edit.

## 7. Rollback

Per runtime, in reverse of the apply, never leave one half back:

- Mac first: `cp $MAC_CONFIG/deployment.json.bak-20261115 $MAC_CONFIG/deployment.json`, restore `soots/builder`, `rm -rf $MAC_CONFIG/packs/lohi-ops && mv $MAC_CONFIG/packs/lohi-ops.bak-20261115 $MAC_CONFIG/packs/lohi-ops`, restart. A detached sweep may still be running: list with `ps aux | rg 'job-runner.mjs'` and stop only the processes whose argument is a `catalog-jobs/radar-*` dir (never a broad `pkill`). Jobs the runner already wrote to prod stay (they are chapters prod lacked).
- Server: restore `flock.json.bak-20261115` and the pack dir, restart. **Pause** the two exec tasks again (`PATCH ... {"repeat": {"state": "paused"}}`) BEFORE restoring the old pack: the old `fix_recheck` and `translate_step` wake the model on every tick.
- Data: nothing to migrate back. `catalog_jobs` rows opened by `policy:radar` that are still `approved` would be started by the old builder as plain refreshes without chapters (a radar run); end them first by inserting `{job_id, state: "failed", detail: "rolled back"}` into the queue `catalog_job_events` (`soot data insert --team operations --queue catalog_job_events --row '<json>'`), which the old sync folds. `translations` rows with `announce` / `rest_*` are ignored by the old pack.
- Quality mail: no state; stop mailing by restoring the curator skill from the backup.
