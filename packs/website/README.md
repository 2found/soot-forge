# Website pack

Requires Node.js 22.13+ (existing publication uses node:sqlite). `use: []` keeps all capabilities opt-in. Select `website/publish` for the bounded landing region, `website/cms` for blog authoring, or `website/care` for maintenance guidance with separately granted tools. The pack grants no shell, arbitrary fetch, source editing, public conversation access, ingress, provider changes or schedules. It is self-contained; install it without rebuilding Soot.

## CMS integration contract

Typed model tools `website_cms_inspect` and `website_cms_save` run fixed `node tools/cms.mjs inspect|save` with the `soot/v1` tool.call stdin envelope. Any Soot the host grants `website/cms` may call them (the envelope must name the calling Soot; the host's grant and credential binding decide who that is). They preserve forward-compatible envelope fields, and reject extra request fields. Inspect uses mode `read`; save uses mode `write`; both use resource `website_cms`, a 10-second executable timeout and 128-KiB output allowance. Only these tools declare `secret_env: {WEBSITE_CMS: "{{cred:WEBSITE_CMS}}"}`. They never print credentials or remote error bodies.

Host-owned `WEBSITE_CMS` is a JSON string with exactly `{origin,site,token}`. Bind it to each Soot that writes posts, for only operations `website_cms_save` and `website_cms_inspect`, sourcing deployment environment reference `SOOT_CMS_CREDENTIAL_JSON`. No model input supplies any of these values. Origin must be a canonical HTTPS origin (no path, query, userinfo or fragment); HTTP is permitted only for loopback fixtures. Site is a lowercase hyphen-separated identifier up to 64 characters; token is nonempty printable ASCII without whitespace, at most 4096 characters. Credential JSON is capped at 8192 bytes. The VM bootstrap additionally pins origin `https://2found.dev` and site `soot`.

Requests send `Authorization: Bearer <token>` and `Accept: application/json`; PUT also sends JSON Content-Type. No cookies, redirect following, HTTP retries or automatic uncertain-effect replay. One **5-second** deadline covers headers and the entire body; at most **128 KiB** response bytes are collected before fatal UTF-8 decoding and JSON/schema validation. Stdin is bounded at 512 KiB including event/envelope metadata, decoded with fatal UTF-8. The fixed Soot runtime caps actual tool input at **16 KiB**, so the complete serialized model request must fit that smaller ceiling. API support for 40,000-byte bodies does not raise the runtime limit.

| Operation | Input / HTTP | Success |
| --- | --- | --- |
| `website_cms_inspect` | Exactly `{slug}`; GET `/api/cms/v1/sites/:site/drafts/:slug` | `{post:{slug,title,summary,bodyMarkdown,author,revision,status,updatedAt,publishedAt,language}}`; legacy language omission accepted; 404 becomes `{post:null}` |
| `website_cms_save` | `{slug,requestId,expectedRevision,title,summary,bodyMarkdown,status}` plus optional `language:"en"|"vi"`; PUT `/api/cms/v1/sites/:site/posts/:slug`, body omits slug | `{post:{slug,title,summary,author,revision,status,updatedAt,publishedAt,language},duplicate:boolean}`; legacy English language omission accepted |

Slug: lowercase alphanumeric segments separated by hyphens, at most 96 characters. requestId: UUID. expectedRevision: nonnegative safe integer (0 for creation after a missing-post inspect). Title: nonblank 1–200 Unicode code points. Summary: 0–500 code points. Body: nonblank, at most 40,000 UTF-8 bytes. Strings reject unpaired surrogates and unsafe control characters. Status: `draft`, `published`, `archived`. Metadata revision is a positive safe integer; timestamps are nonnegative safe integer values, publishedAt nullable for unpublished posts. Response fields are exact, and slug must match. Server owns author/revision/timestamps.

Language is optional on save and defaults to English on the API. The tool validates but **does not insert** it into old payloads: legacy request bytes/receipt discipline remain unchanged. Returned language, when present, must be `en` or `vi`; omission from the old API means English. Save results must match the intended language (a missing/English response for a Vietnamese save is uncertain, not success). Typed output allows optional language for the transition. Inspect exposes the original language presence/value; archive must preserve it. Translation posts use distinct `-en`/`-vi` slugs; existing English slugs stay valid. The interface does not invent translated posts.

HTTP 409 returns `{status:"conflict"}`: stale expectedRevision or requestId reused with a different payload. It is not a successful publication receipt. Other transport/response failures are failures; a failed PUT may already have committed. Inspect latest revision, retain the same requestId and exact payload (including language presence/omission), and reconcile before an explicit identical replay. Never change payload/revision under the old ID or automatically generate a replacement ID. Soot unknown-effect fences may need operator reconciliation before replay. Archival preserves inspected title/summary/body and language with `status:"archived"`. No local CMS receipt store or private database access is added.

`website/publish` remains independent and keeps its existing receipts/resource. Its fixed CTA destinations additionally allow exactly `/blog`, not arbitrary article URLs or external links. Read `skills/cms.md` for authoring/recovery guidance.

Website article Markdown supports simple safe HTTPS `[source label](https://...)` citations, opening a new tab with noopener/noreferrer. Cite real sources; unsafe URLs, HTML, images and embeds stay inert. English `/blog` and Vietnamese `/vi/blog` use public-only SSR reads with the CMS language filter before pagination; source fixtures are not evidence of deployed API/index behavior.

## Verification and activation

`pnpm test` or `node --test tests/*.test.mjs` uses synthetic/local HTTP fixtures only. Host deployment composition and credentials belong to the consuming repository; follow that repository’s deployment runbook. The Pack archive contains no host credentials or deployment state.

The bundle additionally selects `2found/marketing` and only `toolbox/research` for the marketer; this website pack itself does not grant research or start timers. `GITHUB_RELEASES` binds the runtime-only `SOOT_GITHUB_RELEASE_TOKEN` to `2found_releases` only (fixed read-only repository). Its token is 20–4096 printable non-whitespace ASCII characters and distinct from admin/showcase/advisor/visitor/CMS tokens. Reviewed 6h release and 24h provider-digest schedules save private plans and EN/VI article **drafts only**; only explicit operator publication tasks may publish articles by policy. Draft-only is a schedule instruction, not a separate tool-enforced status restriction. Original `website/publish` landing-region behavior remains independent and unchanged.

The operator must provision app-scoped VM CMS/GitHub secrets with least-privilege scopes, install the reviewed source/image and configure a concrete host maintenance/deployment runbook. Starting this configuration activates its timers; none is activated by source QA. Source tests do not prove live auth or API behavior. The provided public documentation URL `https://2found.dev/api/docs/cms.md` returned HTTP 404 during earlier integration; this follows the supplied API contract, not sibling API source. No live CMS write, credential read, production publish, commit, push, deploy or restart is part of this task.
