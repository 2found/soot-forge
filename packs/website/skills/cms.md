# Author the blog archive

Use this opt-in capability alongside website-marketing, not as a replacement for the bounded landing-page region. Real English posts live at /blog; Vietnamese posts at /vi/blog. Add a fixed /blog CTA to the region when useful; no arbitrary CTA URLs. You cannot edit source, choose a host/site/token, run shell, or fetch arbitrary URLs through these tools. Marketing ownership stays with website-marketer, never public visitors or the player.

Before writing or archiving, call website_cms_inspect with {slug}. It reads the latest authenticated draft, including bodyMarkdown, status and revision. post:null means missing: use expectedRevision:0 for creation. A failed inspect is not proof of absence. Existing posts require the inspected revision, not a guessed revision. Preserve content and language when archiving: send the inspected title, summary, bodyMarkdown and language (when present) with status:archived. Missing language from the old API means English.

Call website_cms_save with {slug,requestId,expectedRevision,title,summary,bodyMarkdown,status} and optional language: "en" or "vi". Omission defaults to English; keep legacy English payloads without a new field, especially on receipt replay. For Vietnamese, send language:"vi". Translation posts must have distinct slugs ending in -en / -vi; never invent a translation or overwrite an existing English slug with Vietnamese. Existing English slugs remain valid. Slugs are lowercase alphanumeric segments separated by hyphens, up to 96 characters. requestId is a fresh UUID for a new intended change. expectedRevision is a nonnegative integer. Title is 1–200 Unicode characters, summary 0–500, body 1–40,000 UTF-8 bytes; status is draft, published or archived. The current runtime input ceiling is 16 KiB for the entire JSON input (including escaping and metadata), even though the API permits larger bodies. Keep tool-authored posts under that total limit; do not split/rewrite to bypass it. Metadata author/timestamps/revision belong to the server.

Retain the exact requestId and complete payload before sending. If PUT times out, disconnects, or returns invalid data, the outcome may already be committed. There is no automatic retry. Inspect latest revision; do not infer completion from inspection alone. An explicitly authorized replay must use the same requestId, expectedRevision and byte-for-byte equivalent field values (including language presence/omission), never a new ID or updated revision. duplicate:true confirms the prior identical request. status:conflict means HTTP 409 (stale revision or conflicting ID): inspect and reconcile, never overwrite blindly or recycle an ID with changed content. A new deliberate revision after reconciliation requires a fresh UUID. Runtime unknown-effect fences may require operator reconciliation before replay.

Write honest, evidence-backed posts in the Soot brand. Never invent release, deployment, performance, price, installer availability, testimonials or shipped-feature claims. Examples must be labeled. Article Markdown is safely rendered by the website; simple [source label](https://...) citations become external links opening a new tab with noopener/noreferrer. Use real evidence-backed HTTPS sources. Invalid URLs, images, embeds and raw HTML remain inert. Fenced code is inert. Save as draft when facts need review. Your final reply reports actual receipts/status, not a claimed publication based on an uncertain write.
