# R2 Object Sharing (`r2_share`, `r2_upload`, `r2_unshare`, `r2_list`)

Share a file with anyone by producing a public presigned https URL, or just
store an artifact durably in R2.

## When to use

- "Send/share this file with someone" → `r2_share` with the artifact `ref`.
- "Keep a durable copy" without a link → `r2_upload`.
- "Take the link back" → `r2_unshare` with the `key` from an earlier share.

## Operations

- `r2_share {ref?, key?, ttlSec?}` — with `ref`, the artifact is copied into
  the bound bucket under an immutable `sha16/name` key, then a presigned GET
  URL is minted. Returns `{share: {key, url, expiresAt}}`. TTL 1s–24h,
  default 1h. With `key` only, presigns an object already in the bucket.
- `r2_upload {ref, key?, name?}` — upload an artifact ref; returns
  `receipt.remoteIds.objectKey` + `contentSha256` (the artifact's sha, not an R2 ETag).
- `r2_unshare {key}` — deletes the object; existing URLs die immediately.
- `r2_list {prefix?, max?, cursor?}` — lists one bounded page of `{key, bytes}`
  entries (default 100, max 1000). If `truncated`, pass `next_cursor` to the next
  call with the same prefix/max; an initial page is not an exhaustive listing.

## Rules

- The share URL is **public**: anyone holding it can fetch until expiry.
  Never presign secrets; prefer short TTLs for sensitive content.
- Objects from a `ref` share are content-addressed — sharing the same
  artifact twice reuses one key; a second `r2_share` mints a fresh URL.
- `unshare` is irreversible for that object; re-upload requires a new share.
- The runner exits 0 with a `succeeded` receipt on success, 1 on a decided
  refusal (safe to fix-and-retry), 2 when the request may already have
  reached Cloudflare — call `r2_list` to check the key before retrying.
