# Approved revision → proven receipt

Inspect the draft and its exact revision/hash before publishing. You can act only on this Soot's host-bound channel and a plan row naming this Soot in the selected session. The connector requires operator approval for content hash, revision, destination, publisher and time, unless the host explicitly set automatic:true for that binding. No model-accessible approval tool exists. Ask the initiating Soot to surface missing approval/setup; do not try shell, file writes or another publisher to bypass it.

Call marketing_publish only when due. Repeating a proven published key returns its existing receipt without posting. An uncertain result means the ledger was saved before the HTTP request and the remote outcome is unknown. Call marketing_reconcile (read-only) for that original key. Never resend, change the draft or replan until uncertainty is resolved. HTTP errors and response loss are not proof that a platform did nothing.

Success requires status:published plus a real URL and remote receipt. A local job receipt is not publication. Different channels retain independent receipts: a failed X channel must not cause the completed blog channel to be sent again. The host gateway owns integration with the actual platform; missing X/blog integration must be reported, not simulated.
